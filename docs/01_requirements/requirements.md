# 要件定義

作成日: 2026-09-06  
根拠: `docs/00_concept/initial-request.md`

## 1. 背景と目的

ランニングのパフォーマンスは気温・湿度などの気象条件で変化する。PaceCast は、過去の走行記録と気象データを蓄積し、未来の気象条件でどの程度のパフォーマンスが期待できるかを示す。

本プロジェクトはアプリケーション完成に加え、要件整理からテストまでの開発プロセスを学ぶことも目的とする。

## 2. 利用者

初期は開発者本人（単一ランナー）のみ。ログインや権限管理は行わない。

## 3. 機能要件

### FR-1 気象データの取り込み

- 気象庁の時別値 CSV（気温・相対湿度）を取り込めること
- 1行を1時間の観測として保存すること
- 地点名、観測日時、気温、湿度、品質情報を保持すること
- 同じ観測日時は上書き（再取り込み可能）であること
- 欠測（気温または湿度が空）の行はスキップすること

### FR-2 ランニング記録の登録

- 走行日時、走行距離（km）、走行時間、平均心拍数を登録できること
- 平均心拍数は任意項目であること
- 登録済み記録の一覧・編集・削除ができること
- 走行時間からペース（分秒/km）を算出して表示すること
- 一覧の各行にペースと、紐付いた気象（例: `21.0℃ / 60%`）を出すこと。未関連は `—`

### FR-3 気象と記録の関連付け

- 走行開始日時に最も近い気象観測（1時間値）を自動で関連付けること
- 該当する観測が無い場合は未関連のまま保存し、画面上で分かるようにすること
- 気象を再取り込みしたあと、未関連の記録を再関連付けできること

### FR-4 パフォーマンス予測

指定した気象条件に対して、次を算出・表示すること。

- 予想走行ペース（分秒/km）
- 指定距離に対する予想タイム

予想平均心拍数は結果に出さない。心拍は走行強度（目標 bpm）の指定と、類似走の重み付けに使う。

気象条件の与え方は次の2通りとする。

1. 気温・湿度の手動入力
2. 日時指定（天気予報からその時刻の気温・湿度を取得）

予測には類似気象の過去走を使い、件数と信頼度（高 / 中 / 低）を表示すること。根拠となった過去走も提示すること。

### FR-5 画面

Web ブラウザから、気象の取り込み状況、走行記録の CRUD、予測実行ができること。

## 4. 非機能要件

- ローカルで起動・利用できること（初期は個人利用）
- データはリポジトリ内の SQLite ファイルに永続化すること
- 気象 CSV は Shift_JIS / CP932 を想定すること
- 予測ロジックは説明可能であること（初期は統計、機械学習は将来）

## 5. 初期対象データ

同梱の `data/weather/data.csv` を第一の取り込み対象とする。

- 出典形式: 気象庁 過去の気象データ（時別値）
- 地点: 練馬
- 要素: 気温（℃）、相対湿度（％）
- 期間: 2025-09-05 01:00 〜 2026-09-06 00:00
- 文字コード: CP932
