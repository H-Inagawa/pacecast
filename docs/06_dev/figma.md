# Figma の使い方と PaceCast の画面設計

作成日: 2026-09-19  
根拠: [GitHub Issue #18](https://github.com/H-Inagawa/pacecast/issues/18)

Figma を初めて触る開発者向けです。見た目の本番デザインは Figma に残し、実装は各子 Issue で依頼が来るまでしません（`figma` ラベル）。色はライト／ダークの 2 モード、幅は PC と最新の iPhone / Pixel を見る。

公式の画面説明は [Guide to the Figma interface](https://help.figma.com/hc/en-us/articles/360040328614-Guide-to-the-Figma-interface) です。

## 1. 何をするか

PaceCast の画面はすでに動いています。ラフスケッチはしません。Figma では次を決めます。

- 色（アプリ全体で同じ役割には同じ色。ライトとダークで同じ名前）
- 余白・大きさ・並び（PC とスマートフォン）
- ボタン・モーダル・表などの形。スマホと PC で構造が大きく違うときは、別フレームにする

決めたら、該当する GitHub Issue にフレームの URL を貼ります。未作成なら「未」のままです。ホームの導線を画像付きカードにするときの指定は [#22](https://github.com/H-Inagawa/pacecast/issues/22) です。

## 2. アカウントとファイル

1. [figma.com](https://www.figma.com/) で無料アカウントを作る（Starter で足りる）
2. ブラウザでも [Figma Desktop](https://www.figma.com/downloads/) でもよい
3. Drafts に **PaceCast** というファイルを 1 つ作る（画面ごとにファイルを増やさない）
4. 右上 Share で、チームが開けるリンクにする（「can view」で足りる。編集する人だけ can edit）

ファイル URL（2026-09-20）: https://www.figma.com/design/gznwPOVvkSqEDcIPhknaHr/PaceCast  
共通UI（ダーク）: https://www.figma.com/design/gznwPOVvkSqEDcIPhknaHr/PaceCast?node-id=2-2  
目次 [#18](https://github.com/H-Inagawa/pacecast/issues/18) の本文にも貼る。

## 3. 画面の呼び方

| Figma の言葉 | 意味 | PaceCast での使い方 |
| --- | --- | --- |
| ファイル | 1 つのデザイン一式 | PaceCast 全体で 1 ファイル |
| ページ（左のタブ） | ファイル内の区画 | 「色」「共通UI」「ホーム」…と画面別に分ける |
| フレーム | 1 枚の画面 | PC とスマートフォン、必要ならライトとダークで分ける |
| レイヤー | ボタンや文字などの部品 | 日本語で実名を付ける（`Button/Primary` ではなく「記録を追加」） |
| カラー変数 | 名前付きの色 | トークン名はライト／ダークで共通。有料なら 1 コレクションに 2 モード。無料（Starter）はコレクションを `Dark` と `Light` に分ける |

左側がレイヤー一覧、中央がキャンバス、右側が塗り・線・文字の指定です。

## 4. ファイルのページ構成

次のページを先に作ります。色のページを最初に埋めてから、画面に取りかかります。

1. `00 カラーパレット`（ライトとダークの見本を並べる）
2. `01 共通UI`
3. `02 ホーム`
4. `03 走行記録`
5. `04 パフォーマンス予測`
6. `05 設定`
7. `06 ログイン・新規登録・メール確認`
8. `07 パスワード再設定`
9. `08 分析結果`
10. `09 ランニング天気予報`

各ページに、その画面の GitHub Issue の URL をテキストで書いておくと探しやすいです。

## 5. 色の決め方（ライト / ダーク）

アプリ全体の色は [#18](https://github.com/H-Inagawa/pacecast/issues/18) の「カラーパレット」表が正です。画面別 Issue で個別の Hex を増やさないでください。新しい役割の色が必要なら、先に #18 の表へ行を足します。

ライトとダークは **同じトークン名** で、値だけ変えます（例: `ink` がライトでは濃い文字、ダークでは明るい文字）。部品に直接 Hex を書かないでください。

Figma の変数画面は、左がコレクション、中央が名前と値の表、右が 1 件の詳細です。説明（用途）は右パネルの「説明」に書けます。表の列として説明を出す機能はありません（有料でも同じです）。

[モード](https://help.figma.com/hc/en-us/articles/15343816063383-Modes-for-variables)（1 つのコレクションに Light 列と Dark 列を並べ、フレームで切り替える）は **Starter（無料）では使えません**。Education と有料プランです。[プラン比較](https://help.figma.com/hc/en-us/articles/360040328273-Figma-plans-and-features) では Starter の Variable modes が空欄です。無料のときは次の迂回にします。

### 無料（Starter）での付け方

1. コレクションを **2 つ** 作る（名前: `Dark` と `Light`）。左に並ぶのはモードではなくコレクション
2. 値の列は `Mode 1` のままでよい（コレクションあたりモードは 1 つ）
3. #18 のトークンを **同じ名前** で両方に入れる。**1 行 = 色 1 つ**（塗りと文字は別トークン）。先にダークを決めるなら `Dark` を埋め、同じ名前を `Light` に複製してライトの Hex を入れる。半透明は `#ffffff 不透明度 12%` のように書く（Figma では色に HEX、右に不透明度 %）
4. 右パネルの「説明」に #18 の「UI要素」列をコピーする（例: `muted` → 補足・件数・空メッセージ）
5. キャンバスの `00 カラーパレット` に、用途つきの見本表を置く（変数ビューでは説明が一覧できないため）
6. ダーク用フレームの塗りには `Dark` の変数、ライト用には `Light` の変数を割り当てる。ワンクリック切替はできないので、モード違いの画面はフレームを分ける

`Light` が 0 件のままだとライト用フレームに割り当てられません。名前を揃えてから色だけ変えます。

### 有料 / Education での付け方

1. コレクションは 1 つ（名前例: `PaceCast color`）
2. モードを `Light` と `Dark` の 2 つにする（表の列が 2 つになる）
3. 同じトークンにライトとダークの値を入れる
4. フレームを選んでモードを切り、同じレイアウトで両テーマを確認する

現行アプリはライトのみです。表の「現行ダーク（仮）」は、ライトの色相を保ったサンプルです。ダークを先に決めるときは、この列を `Dark` コレクション（または Dark モード）に入れてから本番ダークへ直してください。

行の色分け（心拍ゾーン・WBGT ゾーン）は意味のある色です。ダークでも 5 段階と未関連が区別できること。似た色に寄せすぎると、表が読めなくなります。

画面フレームの確認は、同じレイアウトを Light と Dark で 1 枚ずつ見ます。無料プランでは変数のモード切替が無いので、ダーク用とライト用のフレームを分けます。構造が同じなら、複製して変数のコレクションだけ差し替えます。

### カードにモノクロ透過画像を載せる

ホームの導線は、塗りつぶしボタンではなく **カード** にし、背景にモノクロで透過した画像を重ねる想定です。並びは上から「パフォーマンスを予測」「走行記録」「ランニング天気予報」「分析結果」「PaceCastとは？」。スマホ寸法は大 320×160（先頭3つ）／分析 320×100／について 320×80。指定は [#22](https://github.com/H-Inagawa/pacecast/issues/22) です。

Figma での重ね方（下から）:

1. カードの塗り（カラー変数。ライト／ダークで変える）
2. 画像レイヤー（PNG。黒いシルエット＋透明。カラーは付けない）
3. 必要なら薄い色のオーバーレイ（文字を読むため）
4. ラベル（`ink` またはカード用の文字色）
5. 「パフォーマンスを予測」「走行記録」「ランニング天気予報」は、ラベルの下に説明用のカード内リード文を置く（文言・字サイズは [#22](https://github.com/H-Inagawa/pacecast/issues/22)）

画像レイヤーは Blend mode を `Luminosity` か `Multiply`（ダークでは `Screen` も検討）、不透明度を数値で残します。画像ファイルは Figma に置き、Issue に「ファイル名 / 題材 / 配置 / 不透明度 / ブレンド」を書きます。

## 6. 位置の決め方（PC とスマートフォン）

Figma のフレーム幅は **CSS ピクセル**（ブラウザが見ている幅）です。端末の物理解像度（例: 1206×2622）では作らないでください。

2026-09 時点の最新系（縦向き）。高さはブラウザのツールバーで減るので、幅を優先します。下部バーはホームインジケータ分の余白（safe area）を見ます。

| 対象 | フレーム幅 × 高さの目安 | 備考 |
| --- | --- | --- |
| PC ブラウザ | 1280 × 800 以上 | 現行の広い画面。必要なら 1440 も可 |
| iPhone 17 | 402 × 874 | [CSS viewport](https://www.webmobilefirst.com/en/devices/apple-iphone-17-2025/) |
| iPhone 17 Pro Max | 440 × 956 | 大きい iPhone。[viewport](https://www.webmobilefirst.com/en/devices/apple-iphone-17-pro-max-2025/) |
| Pixel 10 | 412 × 924 | [CSS viewport](https://www.webmobilefirst.com/en/devices/google-pixel-10-2026/) |

必須で残すフレーム:

| フレーム名の例 | 幅 | 見るもの |
| --- | --- | --- |
| `ホーム / PC 1280` | 1280 | PC ブラウザ |
| `ホーム / iPhone 17` | 402 | 狭いスマホ。下部バー・ドロワー・safe area |
| `ホーム / Pixel 10` | 412 | Android 標準幅。402 と差が小さいので、402 で詰まったあとで崩れ確認でもよい |

Pro Max（440）は、402 と 1280 の間で表や CTA の折り返しが変わるときだけ別フレームにします。横向きは今は必須にしない。

現行 CSS の折り返しは **720px** です。720 前後で並びが大きく変わる部品（表、下部 1:3:1、ホームの大きなボタン）は、PC 用とスマホ用で **別の画面設計図** を検討します。

別フレームにする目安（1 つでも当てはまったら分ける）:

- 表が横に収まらず、カード型の行に変える（走行記録・予測の根拠表）
- 下部バーの 1:3:1 や 3:1 が文字切れ・折り返しで読めない
- モーダルが画面高さに収まりきらず、全画面に近い形にする
- ホームの 2 つの大きな CTA を縦積みにする、など構造が変わる

余白や字サイズだけの差なら、同じ設計図を幅違いで複製し、Auto layout で詰めるだけでよいです。

高さは内容に合わせて伸ばして構いません。フレームは `F` キー、またはツールバーの Frame です。Figma の端末プリセットがあれば使ってよいですが、幅が上の表と違うときは上の表を優先します。

決めて Issue に残すこと:

- 画面端からの余白（左右・上下）
- 部品同士の間隔
- ヘッダと下部操作バーの高さ
- 主要ボタンの高さ（スマホ 412 では下部バー 60px、中のボタン 50px、ページ内の主・副は 100×50）
- 角丸と、枠線の有無

Auto layout（部品を選んで Shift+A）を使うと、余白を数値で持てます。初めてなら、まずフレームに現行画面のスクリーンショットを置き、その上に半透明の四角を重ねて余白を測る方法でも構いません。

## 7. 画面ごとに作るフレーム

各画面 Issue の「UI要素一覧」を上から埋めていきます。一覧の 1 行が、Figma で 1 つ作る箱または図形です。一覧に無い部品を足したくなったら、その Issue に行を足してください。幅と色モードは 6 節・5 節です（「1280 と 390」だけにしない）。

**GitHub で読むとき:** 列が多いと表が横に長くなり読めない。列は `ID / 作るもの / 使うもの / 親 / 状態 / 色 / メモ` 程度に抑え、画面の塊ごとに見出しで表を分ける。カード画像の指定は「カード横断の横長表」ではなく、**カードごとの縦表（項目 | 内容）** にする。

### 状態ごとに画面フレームを分けるか

**全部の状態に画面を増やさない。** ホバーやフォーカスだけで全画面を複製すると、直す場所がすぐ増えます。

画面フレームを分ける（並びや出し入れが変わる）:

- 通常
- 読み込み中（スピナーが出る画面）
- 空（記録ゼロ、WBGT なし、など）
- エラーメッセージ
- ドロワー開・モーダル開
- オンボーディング中（ヘッダ下に流れバー。歯車は出さない）
- その画面特有の構造違い（予測の結果あり、設定の初回、など）

画面フレームは増やさない（部品の別バージョン。`01 共通UI` に並べる）:

- ホバー・フォーカス・無効
- ラジオやカードの選択／未選択（1 枚の画面に両方置いて比べる）
- スクロール固定のヘッダ（見た目が同じなら、高さの指定だけ。スクロール中の重なりを見せたいときだけ 1 枚足す）

**UI要素一覧の行の分け方:** 塗り・文字色・不透明度が状態で変わるものは、**状態ごとに別行**にする（例: カード通常 / ホバー / 押下）。1 行に「通常 / ホバー / 押下」とまとめない。画面フレームは増やさず、部品見本として横に並べる。

### 使うもの（Figma のツール）

子 Issue の「使うもの」列は、次のどれかです。

| 使うもの | キー | いつ使う |
| --- | --- | --- |
| フレーム | `F` | 中に部品を入れる箱。画面全体、ヘッダ、カード、ボタン、入力欄 |
| 長方形 | `R` | 中に何も入れない塗り。オーバーレイ（ドロワー・モーダルの背後） |
| テキスト | `T` | 文字だけ |
| 楕円 | `O` | 丸（スピナー、ヘルプの i） |
| 線 | `L` | 区切り、ハンバーガーの棒 |
| 画像 | 配置 | カード背景の PNG |
| ベクター | ペン / アイコン | 歯車など、線や楕円だけでは足りない形 |

ボタンやカードは長方形ではなく **フレーム** にします（中に文字や画像を入れるため）。フレームを選んで `Shift+A` すると Auto layout になり、余白を数値で持てます。

「親」列は、その部品を入れる箱の ID です。画面そのものに置くときは `画面` と書いてあります。

ログイン系はヘッダを出さない画面と、登録・確認でヘッダ＋オンボーディング案内が出る画面があります。現行の振り分けは次のとおりです。

| パス | ヘッダ |
| --- | --- |
| `/login` `/forgot-password` `/reset-password` | 出さない |
| `/register` `/verify` | 出す（登録の流れ） |
| それ以外（ログイン後） | 出す |

開発者用アカウント（`dev@pacecast.local`）はログイン画面に出さないでください。

## 8. できたら Issue へ

1. Figma でフレームを選ぶ
2. 右上 Share → Copy link（できればそのフレームへのリンク）
3. 画面別 Issue の本文「Figma」欄を URL に書き換える（「未」を消す）
4. 目次 [#18](https://github.com/H-Inagawa/pacecast/issues/18) の表も同じ URL にする

書き出し PNG だけでも構いませんが、色の変数が残るので Figma URL を優先します。

## 9. 実装について

`figma` ラベルの Issue は、デザインを残す場所です。見た目の実装は「この Issue の対応をお願いします」と Cursor に依頼するまでしません。

2026-09-21: 共通UIの実装は、スマホ 412・ダークを先に揃える。色は #18 の現行ライト／現行ダーク（仮）。アプリの日本語フォントは **Kaisei Opti**（本文 Regular / ラベル・下部バー Medium / 見出し・ロゴ Bold）。ヘッダ 70px、入力 35px、ページ内の主・副ボタン 100×50、下部バー 60px・中のボタン 50px。「ホームへ戻る」は幅 120px のまま字を小さくする。ドロワーのログアウトは y:400。ライトと PC 1280 は後回し。ホーム以降の画面レイアウトは各 Issue。

2026-09-22: Figma 上の文字は **Noto Serif JP**（本文 Regular / ラベル・下部バー Medium / 見出し Bold）。レイヤー名の先頭には、その画面の UI要素一覧の ID を付ける（例: `C1 ヘッダ帯`、`N1 走行記録`）。アプリ側のフォント変更は、実装の依頼があるまでしない。
