# 未決事項・検討事項

初期構想時点で不足している要件と、今後具体化が必要な事項。MVP では仮決めして先に進める。

## MVP で仮決めしたもの

| 項目 | 仮決め | 見直し時期 |
| --- | --- | --- |
| 利用者 | メール＋パスワード。走行・設定はアカウント単位。既存データは開発者用と私用 Gmail にコピー | チーム利用や権限を足すとき |
| 地点 | 設定のアメダス地点（未設定時は東京 44132）。走・予報でも上書き可。手動選択は都道府県で絞る（[#51](https://github.com/H-Inagawa/pacecast/issues/51)）。設定は GPS 最寄りも可（[#50](https://github.com/H-Inagawa/pacecast/issues/50)）。記録追加の初期地点は設定で「設定どおり」か「GPS 最寄り」を選ぶ（[#49](https://github.com/H-Inagawa/pacecast/issues/49)） | GPS / Garmin など外部サービスからの取り込みは [#14](https://github.com/H-Inagawa/pacecast/issues/14) |
| 紐付け時刻 | 走行開始時刻の最近傍1時間値。同距離なら早い方。別の1時間値にまたがる走は開始と終了の2点平均（[#48](https://github.com/H-Inagawa/pacecast/issues/48)） | 全時間値平均が必要になったとき |
| 長時間走の気象 | 開始と終了の2点を平均（気温・湿度・風・日射）。推定 WBGT は平均入力から付け直す。短い走は1点 | 全時間値の平均が必要になったとき |
| 走行強度 | 設定の最大心拍から強度別 bpm を算出（個別上書き可）。記録には強度列を持たない | 過去心拍の分位で個人化するとき |
| 予測手法 | 直近重み付きの式モデル（WBGT・距離・心拍の交差・2次）。表示は秒/km | 記録から外れた距離・心拍の外挿は [#44](https://github.com/H-Inagawa/pacecast/issues/44)。分析画面の配置は #12 |
| 予報ソース | Open-Meteo（キー不要） | 公式 API や複数地点が必要になったとき |
| 距離の扱い | 予測時に距離を指定し、ペース×距離でタイムを出す | 距離帯別モデルを入れるとき |
| コース・標高 | 考慮しない | GPS 連携時 |

## まだ決めていないこと

- トレッドミルと屋外を分けるか
- 「全力走」と「余裕走」を予測対象からどう除外／分けるか
- 降水など、WBGT 以外の気象要素をいつ入れるか
- 予測結果をどの期間・どの距離帯まで信頼するかの、R² 以外の定量基準（記録外の外挿は #44）
- データのバックアップ方針（[#17](https://github.com/H-Inagawa/pacecast/issues/17)。対象は Supabase）
- デプロイ先: 公開は Vercel Hobby（[#45](https://github.com/H-Inagawa/pacecast/issues/45) 済み、`*.vercel.app`。独自ドメインは買わない）。データは Supabase（[#46](https://github.com/H-Inagawa/pacecast/issues/46)）。画面の API は Next.js が service_role で Postgres を読む。FastAPI + SQLite は pytest 用

## 構想にあって初期実装に含めない理由

| 構想の項目 | 扱い | 理由 |
| --- | --- | --- |
| 推移グラフ・相関分析画面 | 仮画面（WBGT × ペース） | 詳細な分析・配置は後で。ホームから「分析結果を見る」 |
| 機械学習モデル | 将来 | いまは説明できる式。外挿や当てはまりの改善は #44 |
| 複数ランナー | 将来 | 個人利用で学習サイクルを回す |
| GPS / Garmin 連携 | 将来 | 手入力でデータ項目を確定してから |
