# 記録から外れた距離・心拍の予測（方針）

作成日: 2026-09-29  
根拠: [GitHub Issue #44](https://github.com/H-Inagawa/pacecast/issues/44) の開発者コメント（2026-09-29）と、その壁打ち [ChatGPT 共有](https://chatgpt.com/share/6abb4d2f-945c-83e8-a6e1-955f3fe80633) の「係数を DB に保存する」回答。

2026-09-29 の開発者コメントを受けて実装した。心拍付きが 6 件未満、または心拍の傾きが使えないときは、現行の式モデル（[#43](https://github.com/H-Inagawa/pacecast/issues/43)）に戻る。

## 1. 何を変えるか

現行は WBGT・距離・心拍の交差と 2 次を、直近ほど重い最小二乗で当てはめる。記録の範囲の外では曲線だけが大きく傾き、非常識なペースになる。

次の予測は、その多項式をやめる。次の順でタイムを作る。

1. 走る距離に対する目標心拍を決める
2. 各走行記録を、その目標心拍で走った場合のペースに補正する
3. 目標心拍へ補正したペースを、速い走・直近・予測 WBGT との近さ・予測距離との近さで重み付けし、その平均を基準ペースとする
4. 基準タイムに、一般の WBGT 補正と個人の WBGT 補正を混ぜた倍率をかける
5. 画面には予想ペース・予想タイムに加え、補正率の比較と、いまと同じ信頼度のリード文を出す

走行の生データ（距離・時間・心拍・気象）は補正で書き換えない。

## 2. 計算

速度は km/h、画面と RMSE は秒/km。予想タイムは予想ペース（秒/km）× 指定距離。

学習に使う走は、現行と同じく気象が付き推定 WBGT があるものだけ。心拍が無い走は、この新しい式の学習には入れない。

### 2.1 目標心拍

最大心拍は現行どおり `220 - 満年齢`。設定で上書きされていればその値。

距離に対する最適心拍率は、壁打ちの区分を現行のレース目標と揃えて線形補間する。

| 距離 | 心拍率 |
| --- | --- |
| 5 km 以下 | 95% |
| 5〜10 km | 95% から 92% |
| 10〜21.0975 km | 92% から 88% |
| 21.0975〜42.195 km | 88% から 80% |
| 42.195 km 超 | 80% |

目標心拍（bpm）は最大心拍 × この率。四捨五入は現行の bpm と同じ `round`。

強度のラジオは残す。レース種別のときは上の最適心拍率を使う。設定に種目別の bpm 上書きがあれば、率よりその bpm を優先する。距離指定で楽 / 中 / きついを選んだときは、最適心拍率ではなく設定の強度別 bpm を目標心拍にする。WBGT 補正はそのあと共通である。

### 2.2 心拍から速度

各記録の速度は `distance_km / (duration_sec / 3600)`。

重み付き単回帰で `速度 = a + b × 平均心拍` を当てはめる。重みは次の積。

- 直近: `2 ** (-経過日数 / 180)`（半減期 180 日。現行の λ=0.0075/日 より減衰が遅い）
- WBGT: `exp(-|記録の WBGT − 予測 WBGT| / 5)`
- 距離: `exp(-|記録の距離 − 予測距離| / 5)`
- 心拍: `exp(-|記録の平均心拍 − 目標心拍| / 10)`

シグマは WBGT 5℃、距離 5 km、心拍 10 bpm。半減期とシグマはコードに定数として置く。個人補正の事前強度だけ設定に出す（2.5）。

傾き `b` が 0 以下、または目標心拍・記録心拍のどちらでも予測速度が 0 以下なら、心拍補正は使わない。その予測は現行の式モデルに戻し、画面にその旨を出す。

記録ごとの補正速度は、その走の実速度に、回帰直線上の速度比をかける。

`補正速度 = 実速度 × (a + b × 目標心拍) / (a + b × その走の平均心拍)`

補正ペースは `3600 / 補正速度`（秒/km）。

### 2.3 基準ペース

各記録を目標心拍のペースに補正し、さらにその走の WBGT に対する一般補正で割って、天気の影響をいったん除く。そのペースを、次の積で重み付けして平均する。

- 速いほど重い。最も速いペースから 30 秒/km 遅れると重みは約 0.37 倍
- 直近ほど重い。半減期 180 日
- 予測 WBGT に近いほど重い。5℃ 離れると約 0.37 倍
- 予測距離に近いほど重い。5 km 離れると約 0.37 倍

基準タイムは基準ペース × 指定距離。直線は心拍の換算にだけ使い、基準はその重み付き平均である。

### 2.4 一般 WBGT 補正

補正はタイムへの割合である。最適 WBGT を `W*` とすると、

- 予測 WBGT が `W*` 以上: `(WBGT − W*) × 暑い側の傾き`
- それ未満: `(W* − WBGT) × 寒い側の傾き`

割合 0.035 はタイム +3.5% である。

傾きと `W*` は距離帯（5km / 10km / ハーフ / フル）ごとに、次の図の概形を目視で読んだ近似である。表のセルを1つずつ写したものではない。5km は最適 15℃、10km は 12℃、ハーフとフルは 10℃。暑い側の傾きは 5km の 0.0018 からフルの 0.003（1℃ あたりのタイム割合）。基準ペースが各種目の遅い参照（5km・10km は 300 秒/km、ハーフとフルは 340 秒/km）以上なら、傾きを 1.5 倍する。

- [Mantzios ほか、MSSE 2022（PMC8677617）Figure 5](https://pmc.ncbi.nlm.nih.gov/articles/PMC8677617/)
- Issue #44 に添付の `msse-54-153-s002.docx` の Figure S11 と Figure S12

論文はエリートランナーの記録である。利用者の基準ペースが、図に載っている最も遅い群よりも遅いときは、その最も遅い群の曲線を使う。図の読み取り値は実装時にこの文書へ表で残す。

予測距離が 4 種目の中間なら、両隣の種目の補正率を距離で線形補間する。42.195 km 超はフル、5 km 未満は 5km の曲線を使う。

### 2.5 個人 WBGT 補正と融合

各記録について、心拍だけから見たタイムに対する実タイムの割合を残差にする。

`残差 = 実タイム / 心拍補正タイム − 1`

この残差を、一般モデルと同じ最適 WBGT の寒い側・暑い側に分けて重み付き回帰し、個人の傾き `βcold` と `βhot` を得る。予測時の個人補正率は一般と同じ折れ線で、傾きだけ個人の値を使う。

一般と個人の混ぜ方は次のとおり。

`α = n_eff / (n_eff + K)`  
`最終補正 = (1 − α) × 一般補正 + α × 個人補正`

`K` の初期値は 10 である。壁打ちの 100 は採用しない。階級に分けると 1 階級の件数が少なく、100 のままだと個人補正がほぼ効かないためである。

`K` の未設定は 10。設定画面の「高度な設定」モーダルでアカウントごとに変える（[#56](https://github.com/H-Inagawa/pacecast/issues/56)）。

`n_eff` は重みの和である。ただし全体の和ではなく、予測が落ちる階級の和にする。階級は距離 5 km 刻み、WBGT 5℃ 刻み（`floor(値 / 5) × 5`）。目標階級の記録はそのまま、隣の階級（距離か WBGT が 1 段階だけ違う）は重みを半分にして足す。それ以外は `n_eff` に入れない。階級が空なら `α = 0` とし、一般補正だけを使う。

予想タイムは `基準タイム × (1 + 最終補正)`。

### 2.6 信頼度・RMSE・R²

[#43](https://github.com/H-Inagawa/pacecast/issues/43) の説明と矛盾させない。

- 学習に使った各走について、同じ係数でタイムを予測し直す（標本内）
- 残差は秒/km。RMSE は重み付き平方根。R² は重み付き
- 信頼度は現行どおり、R² が 0.70 以上で高、0.40 以上で中、未満は低
- 参考件数は 2 つ出す。学習に使った全体と、今回の距離階級 × WBGT 階級（隣階級の半分重みは件数に含めず、重み和 `n_eff` は別行で出してよい）

心拍付きで WBGT がある走が 6 件未満のときは、この式を使わず現行の式モデルに戻す。画面のリード文に「心拍付きの記録が少ないため、従来の式で予測した」と出す。

## 3. 画面

予想ペースと予想タイムの 2 枚は、RMSE の幅つきで出す。ペースは `5'00"~6'00"/km (5'30"/km±30"/km)` の形。タイムは同じ RMSE（秒/km）に距離をかけた誤差を、同じ形で出す。予想平均心拍は出さない。

その下に横並びの表を足す。

| | 一般 | 個人補正あり |
| --- | --- | --- |
| WBGT 補正率 | 一般補正を % | 最終補正を % |

個人補正ありのセルは、最終補正の百分率に、一般補正との差を続ける。最終補正の方が大きいときは `+6.1% (一般より3.6%遅くなる)`、小さいときは `速くなる`。個人補正を使わないとき（`α = 0`）は百分率だけ出す。

信頼度・参考件数（全体と階級）・関係の強さ（R²）は、1行のリードにする。RMSE の秒数はリードに出さず、予想ペースと予想タイムの幅に使う。

根拠表の名前は「予測条件に近い走行記録」。重みの大きい 5 件だけ出す。「気象距離」の列は「予測条件との類似性」とし、予測に使った重みを最大 100・小数第2位で出す。その列ヘッダのヘルプに、速い走・直近・WBGT・距離の重みを書く。

関係グラフは 2 枚。WBGT とペース（線は補正後の式）、心拍とペース（線は `速度 = a + b × 心拍`）。`速度(km/h) = a + b × 心拍` は心拍のグラフ上に出す。グラフの上には、基準ペース・補正率・予想ペースの式は出さない。直線が引けていれば、傾きを使わないときも a と b をそのグラフに出す。横軸は予測対象の WBGT・心拍と、最適 WBGT の前後まで含む。予想の点は星にする。従来式に戻ったときは、従来の 3 枚のままである。星は各グラフの予測条件に置く。

「予測の見方」の本文は、多項式の説明をこの式（目標心拍、最速、一般と個人の WBGT、階級、`K`）に書き換える。RMSE が秒/km であることと、信頼度の 0.70 / 0.40 は残す。

## 4. 保存

第 1 段では、係数を予測リクエストのたびに計算する。現行の API と同じで、学習済み係数のテーブルは作らない。走行行も気象行も更新しない。

`K` の列は足さない。設定画面へ出す作業は別 Issue である。

壁打ちにあった `prediction_coefficients`（ユーザー × 距離帯 × 版、切片・傾き・有効サンプル・学習 RMSE）は、モデルの版を比較したくなってから足す。予測結果の履歴テーブルも同じで、今は作らない。

## 5. 実装するときの順番

着手は開発者の明示の依頼があるときだけ。

1. Figure 5 / S11 / S12 から距離帯ごとの最適 WBGT と傾きを読み、この文書の表にする
2. 計算を TypeScript（`web/lib`、予測 API）と Python（`pacecast/services`、pytest）の両方に置く。同じフィクスチャで RMSE と補正率が一致すること
3. 心拍 6 件未満、傾きが使えない、階級が空、距離が遠い、の戻り先をテストする
4. API の応答に補正率・件数・`n_eff` を足す。現行のペース・タイム・RMSE・R² の意味は 2.6 に合わせる
5. 設定の「高度な設定」モーダルに `K` を足す（済。強度別心拍とレースペース心拍もこのモーダル）
6. 予測画面に補正率の表と差の文を足し、関係グラフを WBGT 補正曲線に差し替える。見方モーダルの本文を更新する

## 6. この方針で採らなかったもの

- 壁打ちの事前強度 100。階級を考慮するため 10 にする
- 壁打ちの仮の WBGT 傾き。論文の図を写すまで定数にしない
- 回帰直線の予測をそのまま基準タイムにすること。基準は心拍補正後の最良記録である
- 学習済み係数と予測履歴の DB 保存。第 1 段ではリクエストごとに計算する
- GAM や他の機械学習への置き換え。式を差し替えられる境界は、計算関数を API と画面から分けることで足りる
